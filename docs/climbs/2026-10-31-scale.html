Outcome

Time to push, link, and read an estate of 115,545 entities through the API went from 205,752 ms to 130,010 ms: +36.8% (better). The noise floor was 7.63%, so only changes beyond it were kept.

The held-out score, which the agent never climbed against, went from 104,359 ms to 70,219 ms (+32.7%).

The guard tests passed on the final state.

What changed and why it is better

Pass 1 on an estate of 115,535 entities across 13 blueprints.

  • A push batch writes in a few statements. Each new entity used to cost its own insert, one insert per relation, and one activity row. Now a batch of 1,000 holds them and writes the new entities, their relations, and their activity rows in three statements at the end.
  • Each blueprint’s entities are kept in memory. Every grid, search, picker, summary, finding, and rule used to read a whole blueprint from the database and work out its derived fields again. Now the hub keeps each blueprint’s entities, derived fields and all, until something they read moves. The same events that drop a grid’s kept answer drop them. A caller that adds to an entity copies it first.
  • A copy of a kept entity keeps where its rolled-up reasons came from. Without it, a list filtered on who points at a row would show a restricted reader a reason from a blueprint they may not see. A test covers it.

Tried and not kept:

  • One shared collator for sorting: inside the noise.
  • Looking up a batch’s relations by entity, not by source: on a fresh table Postgres can pick a plan that walks every relation the source wrote once per entity (7.6 s for one lookup; 15 ms with the fix). It measured worse twice, but the whole run was slower in both, because other work loaded the machine. It goes into the next pass, which is scored on CPU time.

What was measured

  • Score: BENCH_SCALE=3 LOG_LEVEL=error node bench/scale.ts \| tail -1, run 3 times per attempt; the median counts.
  • Held-out: BENCH_SCALE=1.5 LOG_LEVEL=error node bench/scale.ts \| tail -1, measured only at the start and the end.
  • Noise floor: 7.63% (spread across 3 baseline runs: 7.63%).
  • Machine: Apple M4 Max, 16 cores, macOS-27.0.

What was tested

Every attempt had to pass these before it was scored:

  • npm run check --silent

Attempts could not touch: .climb/**, docs/climbs/**, bench/**, src/**/*.test.ts, src/server/fixtures/**, package-lock.json. They could only touch: src/**.
